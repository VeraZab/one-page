If you're like me, you like switching between agents now and then. Maybe you're seeing how they compare when one ships a new model, or you're having one review the other's work. Either way, it gets annoying when your setup doesn't come with you — you add a skill or tweak your instructions in one agent, and the other has no idea.

There's no easy way to make everything compatible across agents ([though a few projects are trying](#if-you-need-more)). But three things do port cleanly — your instructions, your skills, and your MCP servers — and setting them up makes the core of your config reusable between Claude Code and Codex. No framework, no sync daemon. Here's each one.

## Instructions: one file for both

This is the single highest-leverage thing you can do, and it takes a minute.

Claude Code reads `CLAUDE.md`; Codex reads `AGENTS.md`. Same idea, different name. So if you're tired of keeping two copies in sync, put the real content in **`AGENTS.md`** and let Claude pull it in:

```md
<!-- CLAUDE.md -->

@AGENTS.md
```

Claude Code expands `@`-path imports, so it reads your `AGENTS.md`; Codex reads it natively.

If most of your frustration is "the two agents don't behave the same," this alone fixes it — your context and rules live in one place now.

## Skills: keep them in Claude, mirror to Codex

Skills feel like they'd be the hard part. They're not. Claude Code and Codex use the **same `SKILL.md` spec** — YAML frontmatter with `name` and `description`, then a markdown body. Only the folders differ: Claude reads `.claude/skills/`, Codex reads `.agents/skills/`.

I mostly live in Claude, so my skills stay in `.claude/skills/` — that's home. To let Codex use them too, just point its folder at Claude's:

```bash
ln -s ../.claude/skills .agents/skills   # Codex now reads your Claude skills
```

Write a skill once, in Claude, and Codex picks it up. You're not fighting the tools to do this — Codex's own docs say it "supports symlinked skill folders and follows the symlink target when scanning." (At the user level it reads `~/.agents/skills`, so symlink that to `~/.claude/skills`.)

Two things to know so you don't get surprised:

- **You trigger them a little differently.** In Claude you run a skill by name with `/skill-name`. In Codex you type `$skill-name`, or `/skills` to pick one from a list. Same skill, slightly different keystroke.
- **Keep the frontmatter plain, and let the rest go.** Stick to `name`, `description`, and your instructions, and the same file runs in both. The tool-specific extras — Claude's `argument-hint` / `disable-model-invocation`, Codex's `agents/openai.yaml` sidecar — don't travel. That's fine. Whatever doesn't port just doesn't.

## MCP: one list, both formats

MCP is the one piece you can't just symlink, because the two tools want different file formats. Claude reads a JSON `mcpServers` object (in `.mcp.json`); Codex reads `[mcp_servers.*]` tables (in `~/.codex/config.toml`). Same servers, different syntax.

So keep one list and generate both. In my repo that's a `servers.json`:

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    }
  }
}
```

and a ~30-line script that turns it into each tool's format:

```bash
node mcp/sync-mcp.mjs
#  -> mcp/claude.mcp.json   { "mcpServers": { ... } }
#  -> mcp/codex.toml        [mcp_servers.context7] command = "npx" ...
```

Point Claude at the JSON (symlink a project `.mcp.json` to it), drop the TOML block into Codex's `config.toml`, and both agents have the same servers. Edit the list, rerun, done. Two things worth keeping in mind:

- **Keep secrets out of the source.** Reference them as `${ENV_VAR}` and let each tool resolve them at runtime — don't bake tokens into `servers.json`.
- **Make failures loud.** You want a bad sync to be obvious and fixable by rerunning the generator, not one agent quietly running stale config.

## What mine looks like

If it helps to see all three wired up, my dotfiles do exactly this at the user level — one `AGENTS.md` for both agents, my Claude skills mirrored to Codex, MCP generated for each, and Claude-only settings kept separate:

```
agent-config/
├── AGENTS.md            ← canonical, symlinked to both agents
├── skills/              ← Claude skills; Codex mirrors them
│   └── draft-pr/SKILL.md
├── mcp/
│   ├── servers.json     ← canonical MCP list
│   └── sync-mcp.mjs     ← generates both formats
├── claude/
│   ├── settings.json    ← Claude-only (permissions, plugins)
│   └── statusline.sh
└── bootstrap.sh         ← recreates the symlinks on any machine
```

It's on GitHub: [github.com/VeraZab/agent-config](https://github.com/VeraZab/agent-config). `bootstrap.sh` is a dozen lines of `ln -s`. That's the whole trick — version-controlled files plus symlinks, reproducible with one command.

## If you need more

Those three shares cover the everyday stuff. A few things genuinely don't port, though — leave these native to each tool:

| If you use...  | Expect to keep it per-tool                                                        |
| -------------- | --------------------------------------------------------------------------------- |
| Slash commands | Claude's `.claude/commands/` vs Codex's prompts (now folding into skills) — adapt |
| Subagents      | Share the definition where supported, native adapter otherwise                    |
| Hooks          | Different runtime models — only sync behavior that's genuinely compatible         |
| Permissions    | Platform security controls — don't weaken them to force parity                    |
| Plugins        | Claude-specific; share the skill _inside_ the plugin, not the plugin              |

And if you'd rather not hand-roll the rest, a handful of community projects try to automate the whole thing. Check their maintenance and actually test them before you depend on one — this space moves fast and advertised features don't always hold:

- [agent-config-sync](https://github.com/B0llerwagen/agent-config-sync) — Claude→Codex sync of skills, MCP, permissions.
- [ai-config-sync-manager](https://github.com/slash9494/ai-config-sync-manager) — bidirectional Claude/Codex sync.
- [ai-agent-config](https://github.com/casoon/ai-agent-config) — unified config via symlinks and generated adapters.
- [universal-agent-skills](https://github.com/26zl/universal-agent-skills) — portable skills across ecosystems.
- [openai/skills `migrate-to-codex`](https://github.com/openai/skills/tree/main/skills/.curated/migrate-to-codex) — official tooling for an initial conversion.

Start with the three that port cleanly. Reach for the rest only when you actually need it.
